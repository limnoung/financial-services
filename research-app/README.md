# DartLab Research · 통합 리서치

**DartLab의 기본 메인화면을 그대로 사용하면서 financial-services 검토 절차와 Gems 매력도 평가를 함께 여는 로컬 프로그램**입니다. DartLab을 별도 창이나 별도 서버로 실행할 필요가 없습니다.

| 구성 | 맡은 역할 | 현재 연결 범위 |
|---|---|---|
| DartLab 0.12.0 | 메인화면·종목 검색·차트·공시·재무·AI 인터페이스 | 공식 배포본 화면과 원래 API를 그대로 사용 |
| financial-services | 경쟁사 비교·가치평가 가정·검산·실적 시나리오 | 입력 점검, 검토 질문, 원문 절차, AI 검토 요청, 보고서 반영 |
| Gems Research | 21개 항목 매력도 평가와 근거 관리 | 정량 계산·정성 평가·미평가 처리·기록·Markdown/JSON 내보내기 |

financial-services는 LLM이 따르는 분석 절차 모음입니다. 설치만으로 동작하는 독립적인 예측 모델이나 DCF 계산 서버가 아닙니다. 통합 앱의 재무 검토는 현재 입력의 날짜·기간·자료 부족을 점검하고 추가 검토 절차를 제공합니다. Excel 수식 감사·DCF 생성·실시간 컨센서스 조회는 구현하지 않았습니다.

## 가장 간단한 실행

Python **3.12 이상**을 설치하고 ZIP을 압축 해제합니다. 전체 GitHub 저장소 ZIP을 받았다면 `research-app` 폴더로 이동하세요.

- Windows: `start.cmd`를 실행합니다.
- macOS / Linux: 터미널에서 `sh start.sh`를 실행합니다.
- 공통: `python -X utf8 start.py`로 실행할 수도 있습니다.

첫 실행에 전용 가상환경과 DartLab 의존성을 설치합니다. 이후 같은 환경을 재사용하며 브라우저에서 **http://127.0.0.1:8766** 을 엽니다. 0.3.1부터 이 포트가 사용 중이면 인접한 다른 포트를 사용하며 실행 창에 정확한 주소를 표시합니다. 브라우저도 이번에 시작한 서버임을 확인한 뒤 엽니다. 첫 화면은 해당 DartLab 배포본의 기본 메인화면입니다. 종료는 실행한 터미널에서 `Ctrl+C`입니다.

브라우저 자동 실행을 끄려면 `python -X utf8 start.py --no-browser`, 포트를 바꾸려면 `--port 9000`을 추가합니다. 설치 오류는 실행한 터미널에 표시됩니다. Python·Node·1TB 금융 데이터를 ZIP에 넣은 실행 파일 형태가 아니라 소스 배포입니다.

## Windows에서 Python 경로 오류가 나는 경우

`Unable to create process using '...Python3.13\python.exe ...start.py'`는 보통 Windows Python 실행기가 이미 삭제되거나 이동한 설치 경로를 가리킬 때 발생합니다. 앱 서버가 시작되기 전의 오류입니다.

0.2.1의 `start.cmd`는 함께 포함된 `start.ps1`로 실제 실행 가능한 Python 3.12 이상을 찾습니다. PATH와 Python 설치 레지스트리, 명시적 버전 실행을 확인하며 잘못된 등록은 건너뜁니다. 시작 파일 일부만 교체하지 말고 ZIP을 새 폴더에 모두 압축 해제해 실행하세요.

먼저 Python 탐색만 확인하려면 명령 프롬프트에서 다음을 실행합니다. 가상환경이나 패키지를 설치하지 않습니다.

    start.cmd --diagnose-python

정상 Python이 없다면 Python 3.12를 설치하고 다시 실행합니다.

    winget install --id Python.Python.3.12 -e

특정 설치를 사용하려면 PowerShell에서 실제 존재하는 경로를 지정할 수도 있습니다.

    $env:GEMS_PYTHON = "C:\Users\사용자명\AppData\Local\Programs\Python\Python312\python.exe"
    .\start.cmd

기존 `.venv`가 삭제된 Python에 연결돼 있으면 그 폴더를 `.venv.broken-...`로 보존한 뒤 새 가상환경을 만듭니다. 기존 환경의 파일과 분석 기록은 삭제하지 않습니다. Windows 실행 검증은 `.github/workflows/research-app.yml`의 Windows 작업에서도 수행합니다.

## ChatGPT 계정에서 Codex 모델 미지원 오류가 나는 경우

`The '...' model is not supported when using Codex with a ChatGPT account`는 현재 Codex 설정의 모델이 로그인한 ChatGPT 계정에서 허용되지 않을 때 발생합니다. 다른 실행환경에서 쓰던 모델 ID가 설정에 남아 있을 수도 있습니다.

0.2.2의 통합 실행은 Codex app-server에서 로그인 유형과 모델 목록을 확인합니다. ChatGPT 로그인에서는 저장된 모델이 계정 목록에 있으면 유지하고, 없으면 목록의 `isDefault` 모델을 사용합니다. 재개한 대화에도 같은 모델을 턴 요청에 전달합니다. 모델 이름을 추측하거나 API 키 인증으로 전환하지 않습니다. Codex 전역 설정·프로필·자격증명 파일도 수정하지 않습니다.

**0.3.1에서는 다음 순서로 복구할 수 있습니다.**

1. 새 ZIP을 새 폴더에 모두 압축 해제하고 `start.cmd`를 실행합니다. 이번 실행에서 자동으로 연 주소를 사용하세요. 기존 창이 열려 있으면 포트가 달라질 수 있습니다.
2. 우측 하단 **AI 연결 점검**을 열고 표시 버전이 **0.3.2**인지 확인합니다. 이 버튼이 없다면 구버전 화면 또는 `dartlab ai`로 실행한 원본 화면입니다.
3. **계정·모델 목록 확인**을 누릅니다. Codex app-server에서 계정 유형·설정 모델·현재 모델 목록만 확인하며 AI 질문은 전송하지 않습니다.
4. 목록에서 계정 기본 모델 등 사용할 모델을 선택하고 **이 모델로 다시 연결**을 누릅니다. 이전에 미지원으로 거절당한 모델은 선택할 수 없습니다. 목록이 비거나 다른 모델이 없으면 Codex CLI의 로그인 상태와 `/model`을 확인하세요.
5. 창을 닫고 AI 채팅에서 질문을 다시 보냅니다. 저장과 재시도 허용은 AI 응답 성공을 뜻하지 않습니다. 실제 답변이 오는지 확인하세요.

앱에서 선택한 모델은 Gems 상태 폴더의 `codex-model.json`에 모델 이름만 저장합니다. 선택 시점과 새 연결 시점에 계정 모델 목록을 재확인하며, 기존 대화도 다음 턴부터 새 선택을 전달합니다. Codex 전역 설정·인증 정보는 수정하지 않습니다. API 키·다른 공급자의 모델 정책도 유지합니다.

이전 Codex 실패가 정확히 ChatGPT 모델 미지원 오류인 경우에만 도달 상태를 **미확인**으로 돌려 재시도를 허용합니다. 원래 오류 내용은 보존하며, 다른 런타임이나 사용량 한도·로그인·연결 오류는 해제하지 않습니다. 서버가 제공한 모델 목록에도 실제 거절당한 모델이 남아 있을 수 있으므로 목록만으로 성공을 단정하지 않습니다. 복구 버튼은 입력한 모델을 다시 목록과 대조하고 이전 거절 모델의 재선택을 차단합니다.

Codex 모델 목록을 조회할 수 없거나 기본 모델을 확인할 수 없으면 임의의 모델로 AI 요청을 보내지 않고 오류를 표시합니다. 이 경우 Codex CLI에서 로그인 상태와 `/model`의 계정 지원 목록을 확인하세요. API 키·다른 공급자를 쓰는 연결에는 이 ChatGPT 모델 대체 규칙을 적용하지 않습니다.

이 호환 보완은 DartLab 0.12.0 Codex 전송 채널에만 적용합니다. 기존 도구·승인 정책·샌드박스·스트리밍 처리는 유지합니다. 검증은 고정된 Codex 프로토콜 응답을 사용하는 회귀 테스트이며 사용자 계정의 실제 AI 답변을 호출한 결과는 아닙니다.

## 한 화면에서 사용하는 순서

1. DartLab 메인화면에서 종목을 검색하고 재무·공시·차트를 확인합니다.
2. 우측 하단 **Gems · 재무 검토**를 누릅니다. 기본 화면 위에 분석 패널이 열립니다.
3. DartLab에 선택된 종목이 있으면 첫 열기에 넘겨 받아 재무 자료를 불러오고 평가 가능한 항목을 계산합니다. 선택된 종목이 없으면 패널에 종목코드를 입력하고 불러옵니다.
4. **재무 검토**에서 기준일·CAGR 기간·업종 기준·경쟁사·목표가 근거·리스크의 입력 상태를 확인합니다. 네 가지 financial-services 원문 절차도 열 수 있습니다.
5. **매력도 평가**에서 나머지 정량 수치와 정성 점수, 근거·출처·기준일을 보완합니다. 모든 자료를 자동으로 찾아 점수를 확정하는 기능은 아닙니다.
6. **보고서**에서 결과를 확인하고 Markdown·JSON으로 내보내거나 분석 기록을 저장합니다.
7. **AI 검토 요청 복사**를 눌러 DartLab AI 채팅 또는 Gemini Gems에 붙여 넣어 검토합니다. AI가 제안한 근거를 앱에 반영해 점수를 다시 계산합니다.

패널을 닫아도 DartLab 기본 화면과 입력은 유지됩니다. DartLab에서 다른 종목을 선택하면 패널 상단의 조회 종목이 갱신됩니다. 평가 입력을 바꾸려면 **현재 종목 가져오기**를 누릅니다. 기존 입력이 있을 때는 교체 여부를 확인합니다. 최신 조회가 실패하면 오류를 표시하며 이전 기업의 수치를 새 기업의 값으로 바꾸지 않습니다.

DartLab AI 기능은 DartLab에서 지원하는 에이전트 실행환경의 설치·로그인 상태에 따라 사용할 수 있습니다. **기본 데이터 조회와 규칙 채점에는 LLM 키가 필요하지 않습니다.** 이 앱이 AI 계정을 자동 연결하거나 AI 요청을 자동 전송하지는 않습니다.

## 설치 환경이 이미 있는 경우

이 폴더에서 실행합니다.

    python -m venv .venv

Windows PowerShell:

    .\.venv\Scripts\Activate.ps1
    python -m pip install -e ".[data]"
    gems-research serve

macOS / Linux:

    source .venv/bin/activate
    python -m pip install -e ".[data]"
    gems-research serve

`serve`는 DartLab 메인화면과 Gems 패널을 같은 서버에서 실행합니다. DartLab 설치 파일이나 UI 번들을 수정하지 않습니다. 내부 API와 UI의 호환 범위를 `dartlab==0.12.0`으로 고정했습니다.

기존 독립 Gems 화면만 필요하다면 `gems-research serve --standalone`을 사용합니다. 이 모드는 DartLab 없이 `python -m pip install -e .`로도 사용할 수 있습니다. 통합 화면은 `[data]` 설치가 필요합니다.

DartLab만 별도로 실행해 보고 싶다면 같은 가상환경에서 `dartlab ai`를 실행하면 됩니다. 기본 주소는 http://127.0.0.1:8400 입니다. 이 명령으로 연 원래 DartLab 화면에는 이 앱의 Gems 패널이 추가되지 않습니다. 통합 실행에는 `start.cmd` / `start.sh` / `gems-research serve`를 사용하세요.

## 차트를 보면서 향후 가격 경로 확인

우측 하단 **차트 전망** 또는 패널의 같은 이름 탭을 엽니다. 기본은 **20거래일**이며 5·60거래일을 선택할 수 있습니다. 과거 종가와 예상 경로·과거 오차 기반 80% 참고 범위를 한 차트에 표시합니다. 범위나 검증에 필요한 이력이 부족하면 해당 결과를 미산출로 남깁니다.

DartLab의 AR(1)·평균 로그수익률 계산을 사용하며, 종가 유지 방식과 과거 구간 오차도 비교합니다. 가격 전망에는 LLM 로그인이나 재무 파일이 필요하지 않습니다. Gems 매력도·목표주가에 자동 반영하지 않습니다. 출처·가격 기준일·가상 예시 여부를 확인하고 사용하세요.

자세한 산식과 검증 범위는 [차트 전망 가이드](FORECAST_GUIDE.md)에 있습니다. 별도 창에서 DartLab을 다시 실행할 필요가 없습니다.

## 데이터와 채점 범위

DartLab 메인화면은 시장 요약 파일과 필요한 상세 파일을 조회합니다. Gems의 한국 재무 조회는 회사별 파일, 미국 재무는 공개 표준화 파일을 사용합니다. 전체 1TB 데이터를 미리 받지 않습니다. 첫 화면과 첫 종목 조회에는 인터넷이 필요할 수 있습니다.

한국장 기본 자동 연결은 **매출·순이익 3년 CAGR, 부채비율, 보통주 배당, 52주 최고 종가 대비 하락률, 50·200일선의 6개 항목**입니다. 자료가 충분할 때만 채점합니다. 미국장은 배당을 제외한 5개 항목을 연결합니다. 나머지는 뉴스·컨센서스·시장 점유율·비교군·정성 판단 등의 근거를 보완해야 합니다.

0.3.2에서는 DART 회사별 `report` 파일의 완결 연간 보통주 배당수익률·지급 이력을 연결했습니다. 현재가 기준 수익률과 구분하며 우선주·분기 누적값을 사용하지 않습니다. 전년 비교나 액면 기준을 확인하지 못하면 배당 자동 채점도 보류합니다. 접수번호에 따른 정정·공개일을 확인하고 공시 원문 링크를 남깁니다.

정부 가격 파일이 없거나 짧으면 회사별 KRX 과거 파일도 조회합니다. 원종가·등락률이 겹치는 5개 날짜 이상에서 일치하는 경우에만 이력을 합쳐 분할을 다시 추론합니다. 값이 다르거나 기간을 대조할 수 없으면 합치지 않으며, 충족률을 올리려고 최신의 짧은 파일을 오래된 긴 파일로 바꾸지 않습니다. 로컬 캐시 모드에서는 두 파일 모두 다운로드하지 않습니다.

**평가 자료 충족률은 21개 항목에서 채점 가능한 가중치의 합이며 API 연결 성공률이 아닙니다.** 재무 3개만 확보되면 15.83%가 맞습니다. 배당까지 확보하면 19.17%, 가격 2개까지 확보하면 29.17%입니다. 한국장에 연결된 자동 자료가 모두 있어도 나머지 15개 조사·검토 항목을 채우지 않으면 100%가 되지 않습니다. 부족한 항목을 3점 등으로 대신 채우지 않습니다.

요약 카드의 **미평가 사유와 보완할 자료**에서 조회 실패·가격 기간 부족·추가 조사 필요를 확인할 수 있습니다. 항목명을 누르면 해당 입력으로 이동합니다. 입력이 바뀌면 이전 충족률을 숨기고 재계산을 요청합니다. 미조회 사유는 근거 JSON·저장 기록·보고서에도 보존됩니다.

0.3.2의 삼성전자 검증은 DartLab 저장소의 고정 공시·재무·가격 파일을 로컬 캐시에 넣어 수행했습니다. 해당 가격은 2026-01-02~2026-07-31의 142개 종가여서 가격 2개 항목은 미평가이고, 배당 추가 후 4/21개·19.17%였습니다. SK하이닉스·SK텔레콤·신한지주 자료도 확인했습니다. 현재 실행 환경에서 Hugging Face 다운로드가 차단되어 최신 원격 파일의 실시간 갱신은 검증하지 못했습니다. KRX 이력 병합의 수치 일치·불일치 검증에는 통제된 가격 시계열을 사용했습니다.

21개 항목이 모두 평가됐을 때 최종 점수를 표시합니다. 자료가 빠지면 잠정 점수·자료 충족률·가능한 범위를 표시합니다. 금융업·리츠·적자 성장기업에는 일반 PER·PEG·부채비율 기준 적용을 보류합니다. 자세한 정의는 [평가 기준서](GEMS_SCORING_GUIDE.md)를 참고하세요.

가격은 공개 파일의 종가이며 실시간 시세가 아닙니다. 조회 성공이 최신 공시·시세 반영을 보증하지는 않습니다. 목표주가는 사용자가 별도 가치평가 근거와 함께 입력하며 매력도 점수로 역산하지 않습니다.

## 로컬 데이터 위치

- `GEMS_DARTLAB_DATA_DIR`: DartLab 서버와 Gems 조회가 공유할 공개 파일 캐시 경로.
- `GEMS_STATE_DIR`: 분석 기록 SQLite를 보관할 폴더.
- 미설정 시 사용자 캐시·데이터 폴더 아래 `gems-research`를 사용합니다. DartLab 자체의 AI 상태는 DartLab의 `DARTLAB_HOME` 설정을 따릅니다.

PowerShell 예시:

    $env:GEMS_DARTLAB_DATA_DIR = "D:\ResearchData\dartlab"
    $env:GEMS_STATE_DIR = "D:\ResearchData\gems"
    .\start.cmd

패널의 **로컬 캐시만 사용**은 Gems 회사 자료 조회에 적용됩니다. 캐시가 없으면 다운로드하지 않고 오류를 표시합니다. DartLab 기본 화면 전체를 오프라인으로 바꾸는 설정은 아닙니다. DartLab 메인화면의 브라우저 캐시와 서버 공개 파일 캐시는 별개입니다.

JSON 내보내기는 입력 근거를 저장합니다. 분석 기록은 입력·점수·기준 버전을 로컬 SQLite에 추가하며 이전 기록을 덮어쓰지 않습니다. 프로그램 코드·데이터 캐시·개인 분석 기록은 분리해 보관합니다.
